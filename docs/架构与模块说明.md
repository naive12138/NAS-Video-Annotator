# 架构与模块说明

## 1. 总体架构

分层 + 流水线，全部单机运行：

```
GUI（PySide6 桌面，非 Web）
  └─ 分析引擎（pipeline + task_queue）
       ├─ 视频源适配（local / jellyfin → 统一 VideoSource）
       ├─ 媒体处理（ffprobe / 抽帧 / 场景切分 / 音轨）
       ├─ 模型（ollama_client 视觉/文本，asr 转写）
       ├─ 汇总（summarize + parse）
       └─ 回写（condense + writers: txt/nfo/jellyfin）
  └─ 存储（SQLite，store.py）
  └─ 配置（config.py，便携 data\ 目录）
```

核心原则：`core/` 不依赖任何 GUI，可被 CLI 或测试单独调用；GUI 只是前端。

## 2. 模块职责

| 模块 | 职责 |
|------|------|
| `config.py` | 唯一配置入口。默认 `data/config.json`；`storage` 始终按 exe/项目根目录计算，忽略配置里的旧绝对路径 |
| `readiness.py` | “测试”按钮后端：只检测服务可达 + 模型已安装，不推理 |
| `store.py` | SQLite 读写：视频/任务/场景/帧/转写/标注/回写记录/错误；检索；删除 |
| `media.py` | ffprobe 元数据、ffmpeg 抽帧/音轨、PySceneDetect 场景切分；`_find` 多位置查找 ffmpeg |
| `ffmpeg.py` | ffmpeg/ffprobe 检测、多源一键下载并解压到 `data/bin` |
| `summarize.py` | 提示词常量 + 视觉 JSON 解析（`parse_vision`）+ 汇总 JSON 解析（`parse_annotation`） |
| `condense.py` | 标注 → 精简回写文本（题材/人数/简介/剧情/标签） |
| `writeback.py` | 回写执行：按数据源自动选 writer，写结果与失败都落库 |
| `pipeline.py` | 单视频流水线编排 + 进度回调 + 失败标记 + 完成后自动清理临时文件与卸载模型 |
| `task_queue.py` | 线程池受限并发执行分析，状态/进度回调 |
| `sources/` | `VideoSource` 抽象；`LocalAdapter` 扫目录；`JellyfinAdapter` 走 API + 流地址 |
| `models/` | `OllamaClient`（自动探测 Ollama/OpenAI，含视觉 image_url、unload）；`asr`（faster-whisper 封装，兼容 text=None） |
| `writers/` | `TxtWriter`、`NfoWriter`、`JellyfinWriter`；`writer_for` 按数据源自动选择 |
| `gui/` | 6 个页面：设置 / 媒体库 / 分析任务 / 日志 / 检索 / 错误 |

## 3. 分析流水线

```
run(video, on_progress)
  1. 读视频信息（ffprobe）                     5%
  2. 场景切分（PySceneDetect）                  15%
  3. 抽帧（场景代表帧 + 均匀帧，逐视频独立目录）  25%
  4. 逐帧视觉理解（LLM 出 描述 + 人数）          30%~85%
  5. 音轨转写（faster-whisper，失败不中断）        —
  6. 汇总（LLM 出 题材/剧情/标签）               85%
  7. 保存标注 + 回写（按数据源自动）              95%
  8. 完成：清理临时文件 + 卸载模型               100%
```

- Jellyfin 源分析用 `stream_url`（`/Videos/{id}/stream?static=true&api_key=...`），不读服务器内部路径。
- 每处理完一个视频：删除该视频的 `data/frames/{vid}` 临时目录，并尽力卸载模型（Ollama `keep_alive=0`）。
- 失败：视频标记 `failed`，完整 traceback 记入错误表。

## 4. 回写规则

| 数据源 | 规则 |
|--------|------|
| 本地 | 有同名 `.nfo` → 写 `<plot>`/`<outline>`（其余字段不动）；无 `.nfo` → 写 `简介{视频名}.txt`（`{视频名}` 为不含扩展名的主文件名） |
| Jellyfin | `POST /Items/{id}` 更新 `Overview` |

txt 命名模板与“已存在时（继续写入 / 新建(1) 顺延）”在设置页配置。

## 5. 配置 schema（config.json）

```json
{
  "ollama":   { "base_url": "http://127.0.0.1:11434", "timeout_s": 3 },
  "models":   { "vision": "qwen2.5vl:7b", "llm": "qwen2.5:7b", "asr": "small" },
  "local_paths": { "roots": [], "extensions": [".mp4", ".mkv", ".avi", ".mov", ".ts", ".m4v"] },
  "jellyfin": { "enabled": false, "base_url": "http://192.168.1.10:8096", "api_key": "" },
  "analysis": { "frame_interval_s": 60, "frames_per_scene": 2, "scene_threshold": 27.0, "segment_sec": 300 },
  "output":   { "txt_name": "简介{filename}.txt", "txt_mode": "new", "txt_encoding": "utf-8-sig" },
  "storage":  { "data_dir": "...", "frame_cache_dir": "...", "db_path": "..." },
  "runtime":  { "workers": 1 }
}
```

说明：`storage` 三项运行时自动按 exe/项目目录计算并覆盖（便携），不依赖配置文件里的旧值。

## 6. 数据库表（SQLite，`data/nasva.db`）

`videos`、`analysis_runs`、`scenes`、`frames`、`transcripts`、`annotations`、`writebacks`、`errors`。
详见 `app/db/schema.sql`。标注的 `tags` 以 JSON 字符串存储。

## 7. LLM 客户端

`OllamaClient` 自动探测接口类型：
- Ollama：`GET /api/tags`、`POST /api/generate`
- OpenAI 兼容：`GET /v1/models`、`POST /v1/chat/completions`（视觉走 `image_url` base64）

`unload()`：Ollama 用 `keep_alive: 0` 卸载；OpenAI 兼容接口忽略。

## 8. 提示词

- 视觉（逐帧）：`VISION_PROMPT` —— 要求如实描述 + 数人数，输出 JSON `{"description","people"}`。
- 汇总（全片）：`build_summary_prompt()` —— 要求客观如实提炼，输出 JSON `{"genre","genre_confidence","one_line","summary","tags"}`。
- 均含“不得回避/美化/省略露骨情节、不做道德评判”的约束，避免模型自我审查。

## 9. 扩展点

- 新视频源：实现 `VideoSourceAdapter`，返回 `VideoSource`。
- 新回写目标：实现 `ResultWriter`，在 `writers/__init__.py` 的 `writer_for` 中接入。
- 新模型运行时：扩展 `OllamaClient` 或新增客户端，替换 `pipeline` 中的注入。
